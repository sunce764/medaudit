## Read the A/B comparison

`python tutorial/make_demo.py` prints four sections. In A and B, the class signal,
noise, sample size, patient structure, and class–mode correlation are identical;
only the added mode signal changes (`beta=0.0` versus `1.2`).

| Probe AUROC | A: class signal only | B: additional mode signal |
|---|---|---|
| Overall | 0.841 [0.796–0.884] | 0.905 [0.873–0.933] |
| Within benign | 0.551 [0.488–0.620] | 0.786 [0.734–0.835] |
| Within malignant | 0.571 [0.510–0.629] | 0.768 [0.713–0.821] |

Brackets are the reported 95% cluster-bootstrap intervals. These are synthetic
probe results, not the diagnostic classifier's disease AUROC. The report's
positive rule uses a CI lower bound above **0.60**; 0.5 is a random-ranking
reference, not the verdict threshold. See tutorial §2 for the full explanation.

**Pause:** B decodes mode within both classes. Did the diagnostic classifier use
that information?

**Answer:** this test does not establish that. `SHORTCUT ENCODED` means information
is available as a potential shortcut. It is not proof of reliance, harm, or
clinical suitability. A's `AMBIGUOUS` result is also not proof of safety.

## Read the leakage output

C generates 480 rows of 64-dimensional features. Its split is generated by the
tool, so group leakage is explicitly `NOT ASSESSED`: there is no original split
to investigate. Near-duplicate search still runs.

D generates 180 rows and intentionally assigns one row from `patient0` to test
while that patient's other rows remain in train. The output must contain
`GROUP LEAKAGE`. Small-subgroup/one-class warnings in D are intentional: mode
and diagnosis are collinear in this example, so some probes are not estimable.

**Pause:** a generated split has no patient overlap. Does that clear the split
used to train your original model?

**Answer:** no. Supply that actual split of record. Near-duplicate flags also
need inspection: cosine similarity and a threshold of 0.90 do not establish
image identity. The CLI prints a verdict and exits 0 even for D; callers must
interpret the report rather than use the exit code as a quality gate.

The CLI saves to `report.txt` by default and overwrites that destination. Use the
separate `--out tutorial/demo/...` paths in the README to retain C and D together.

## Calibration and prevalence worked examples

```bash
python tutorial/worked_examples.py
```

Expected output includes:

```text
AUROC: 0.938
Top-label ECE (4 equal-mass bins): 0.300
Multiclass Brier (sum over both classes): 0.250
  prevalence=50%: PPV=0.947
  prevalence=10%: PPV=0.667
  prevalence=1%: PPV=0.154
```

The eight probability rows and labels are defined inside the script. They are a
small arithmetic exercise, not a calibration estimate for a medical population.
`probs` has shape `(N, C)` and `labels` contains integer class indices. ECE and
reliability bins describe **top-label confidence versus correctness**, not the
positive disease probability curve. The Brier implementation sums over classes;
for two classes it is twice the convention using only positive-class squared
error. Empty reliability bins print `nan, nan, 0`; they are not corrupt data.
The ECE example uses equal-mass bins; `reliability_curve` uses equal-width bins.

The prevalence calculation holds sensitivity=0.90 and specificity=0.95 fixed.
**Pause:** why does PPV fall to 0.154 when prevalence is 1%?

**Answer:** false positives from the much larger negative population outnumber
true positives. This arithmetic assumes unchanged operating characteristics;
real domain changes may violate that assumption. It is not an external-validation
experiment or an extra `medaudit audit` module. Tutorial §4–§5 connects the
calculation to its interpretation.

## Use your own features

Only proceed with inputs you are permitted to use. Feature extraction belongs
to your model/framework; this repository neither downloads nor trains that model.
The audit fits separate metadata probes on the features you supply.

Create a local CSV with `path,label,group,attr_mode` and, to assess your real
split, `split`. Each row corresponds to one row of a finite `(N, D)` NumPy
feature matrix. `group` must represent the patient/case clustering appropriate
to your data. Preserve row order; matching row counts alone cannot detect a
permutation. Metadata probes support binary and multi-class attributes. For
multi-class attributes, the point estimate is the macro-average of the evaluable
one-vs-rest AUROCs. The displayed interval is the widest individual one-vs-rest
confidence interval, **not a confidence interval for the macro-AUROC**.

A minimal `audit.json` alongside your inputs:

```json
{
  "manifest": "manifest.csv",
  "features": "features.npy",
  "probe": {"attributes": ["mode"]},
  "leakage": {"threshold": 0.90}
}
```

Input paths are relative to the config file. `--out` is relative to your current
working directory; its parent directory must exist.

```bash
medaudit audit --config /path/to/local/audit.json --out /path/to/local/report.txt
```

This is a template for your own inputs, not a further runnable synthetic command.
Inspect warnings, subgroup counts, source split, flagged pairs and each verdict's
limits before interpreting any metric. Do not commit private inputs or outputs.

## If a command fails

- `medaudit` not found: activate the environment used by `python -m pip install`.
- Missing `tutorial/demo/audit.json`: run `python tutorial/make_demo.py` first,
  from the repository root. A fresh clone contains code, not generated inputs.
- Feature/manifest mismatch: regenerate the matching demo pair or check the row
  alignment of your own inputs; do not substitute one demo's feature file for another.
- `matplotlib` missing: it is needed only by `make_figures.py`; install the
  `figures` extra if you want to regenerate the charts.
